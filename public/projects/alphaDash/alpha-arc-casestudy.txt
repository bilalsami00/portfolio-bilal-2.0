OVERVIEW

ALPHA ARC Admin Dashboard is a Next.js web application that serves as the operations panel for the Alpha Arc product. It is frontend-only: business data and persistence live in an external REST API, and media files are stored in AWS S3. Administrators use the panel to manage app users and teams, schedule daily quotes, publish audio and video content, review support tickets, and set Android/iOS app version numbers. The browser UI talks to domain service modules over a shared axios client; in the browser those calls are same-origin and proxied to the backend by Next.js rewrites to avoid CORS. Authentication is JWT-based (admin login), with session presence checked by middleware and a client ProtectedRoute. Access is single-role: any successful admin login grants full dashboard access.

PROBLEM & SOLUTION

Problem:
A mobile-facing product needs centralized administrative control over users, team membership, scheduled daily content, and media libraries without building that tooling into the mobile app itself. Operators also need a reliable way to upload or link media, handle support tickets, and publish app version numbers used by clients. The original product motivation beyond this operational need is not documented in the repository and remains [NEEDS CONFIRMATION].

Solution:
The implemented dashboard provides authenticated admin screens that call backend APIs through a Next.js rewrite proxy and upload files directly to S3 via backend-issued presigned URLs. Feature areas follow a consistent pattern: a container page owns fetch/mutation state; shared UI (GenericTable, search, pagination, drawers/modals) presents data; service modules encapsulate each API domain. Route protection combines cookie-aware middleware with client-side token checks. Sidebar navigation exposes the active admin workflows (users, teams, quotes, audios, videos, help & support, settings), while some earlier modules remain in code but are hidden from the menu.

FEATURES

Admin authentication and password reset
- Login against `/api/auth/admin-login` (proxied), with client validation for email/password.
- JWT stored in localStorage and mirrored in a client-readable `session_token_client` cookie so middleware can gate `/dashboard`.
- Forget-password → OTP → new-password flow with sessionStorage-held reset state.
- Logout clears tokens/cookies and navigates to login; axios responds to HTTP 401 by clearing session and redirecting to login.

Users management
- Paginated list with search/filters; user detail drawer.
- Restrict/unrestrict, delete, edit habit/win streaks, send/resend team invites.
- Team-request workflows (sales-tab / appeal style requests) with assign-team UI integrated against backend endpoints.
- Hybrid search: normal browsing is server-paginated; active search can fetch a larger set and filter client-side.

Team management
- Create, update, delete teams; search and paginate team lists.
- Team detail via dynamic `/dashboard/team-management/[slug]` using slug helpers and a module-level/session cache for resolution.
- Assign members, edit/remove members, display/send team codes; existing-user invite flows integrated with the API.

Quote of the Day
- Schedule and manage quotes against calendar dates (reserved dates handled in the UI).
- Create, update, delete via quotes API; search/pagination patterns shared with related daily-content code.
- Buzzwords pages/services still exist in the codebase but are not currently exposed in the sidebar menu.

Audio content libraries
- Daily Drop, Guided Breathwork, and Guided Meditation CRUD.
- Upload audio and thumbnails to S3 using presigned URLs, then persist metadata (title, author, description, duration, etc.) through the API.
- In-app audio playback considerations are reflected in commit history and UI (timer/playback edge cases addressed during development).

Video content libraries
- Weekly Lessons and Sales Training management.
- Current flow requires YouTube URLs (validated for common youtube.com / youtu.be / shorts / embed / live forms); direct video file upload for these screens is disabled in favor of URL-based videos.
- Thumbnail upload remains supported; legacy non-YouTube URLs can be preserved unchanged on edit.
- Video-of-the-day and related older media-library paths exist but are not primary sidebar entries.

Help & Support
- Lists user-submitted support tickets from the support API, with search, pagination, and a view modal.

Settings
- Load and update Android and iOS app version strings (semver-style validation such as `1.0.0`) via version API endpoints.

Shared dashboard UX
- Responsive sidebar navigation driven by `menuConfig.ts`.
- Reusable GenericTable, drawers, confirm modals, empty states, loaders, and toast feedback (custom toast context on dashboard; react-hot-toast on auth screens).

Present in code but not primary / incomplete relative to sidebar config
- Sales Manual (Reps Checklist, Fundamental Scripts, Sales Bible), Leaderboard, Hall of Fame, and Hood Status pages remain in the repo and may be URL-reachable, but their menu entries are commented out.
- Hall of Fame backend proxy rewrites are commented out, so those API calls cannot reach the backend in the current Next config.

CHALLENGES

Same-origin API proxying
- Every backend path used by the UI must be declared in `next.config.ts` rewrites; missing entries fail against the Next server rather than the API. This couples frontend service methods to proxy configuration.

Auth across server and client layers
- Session is a JWT held in localStorage plus a non-HttpOnly client cookie for middleware visibility. Guards check presence rather than validating token expiry at the edge. Password-reset route gating that once used short-lived cookies is largely client-side now. Documented security notes in the repo call out token storage and logging risks as deployment considerations.

Media upload pipeline
- Presign → direct browser PUT to S3 → metadata create/update must stay consistent across audio/thumbnail (and historically video) flows, including MIME/size validation and error surfacing in drawers.

Team detail routing and cache
- Slug-based team detail depends on cache/sessionStorage population; direct loads refetch the team list to resolve slugs, which required careful tab/member refresh behavior (addressed in commit history).

Backend response variance
- Services and pages defensively unwrap multiple response shapes (`data.data` vs `data.items`, alternate field names). That flexibility aids integration but weakens typing (`any` at API boundaries).

Responsive admin UI
- Commit history and shared layout/sidebar work show iterative fixes for overflow, drawer text, and mobile/desktop layout across dense tables and modals.

Incomplete or shadowed modules
- Keeping menu-hidden and rewrite-disabled features in-tree creates ambiguity about what is production-ready versus residual. Hall of Fame is a concrete example where UI exists but proxy routes are disabled.

LESSONS LEARNED

A rewrite-based BFF-style proxy keeps the browser CORS-free, but it makes “add an API” a two-file change (service + rewrite) and rewards keeping those lists synchronized.

Separating upload bytes (S3 presigned PUT) from metadata writes (REST) reduces backend payload size and keeps the admin UI responsive for large media, provided client validation and error handling stay explicit.

Feature-first folders plus shared table/drawer primitives scale well across many similar CRUD screens, but unused dependencies (React Query) and parallel toast systems show that scaffolding should be wired end-to-end or removed to avoid false architectural signals.

Presence-only session cookies are simple for an internal admin tool, yet they push real authorization and token lifetime enforcement onto the backend; frontend guards alone are not sufficient security. Review of the in-repo security documentation before production hardening remains [NEEDS CONFIRMATION] as a process lesson for the deploying team.

Distinguishing active sidebar features from URL-reachable but menu-hidden or rewrite-disabled screens is important when describing scope to stakeholders—code presence is not the same as shipped admin capability.
